# Security review — Microsoft To Do MCP

Reviewed on 2026-11-18 from upstream revision `83d8f44`, followed by verification of the local working tree on macOS ARM64, Node 24.22.1 and pnpm 12.21.0. The review covered the CLI, MCP transport and all tool handlers, Graph adapters, OAuth/device flow, cache, schemas, logger, install/build scripts, CI and dependency graph.

**Assessment.** Suitable for a controlled first connection after you configure a dedicated registration, review consent and accept the local cache and Codex data boundaries below. This assessment assumes a trusted macOS user session and checkout. Live consent, Microsoft-issued account and token claims, and task operations on Microsoft's service remain unverified. No account sign-in was started and no personal credential cache was inspected.

## HTTP, content and operations

The allowed resource tree is lists → tasks → checklist items, rooted at the signed-in user's To Do endpoint. Linked resources may be returned as data; the server never opens their URLs. A separate pinned identity transport allows Microsoft discovery, device-code and token requests, suppresses SDK metric fields, rejects redirects and bounds responses and request time. Credential-bearing OAuth POST bodies make redirect control important even without a Graph Authorization header. The identity redirect concern was identified during source review. No redirect by Microsoft was observed. A real MSAL client with fake credentials and mocked HTTP verified the refresh request and its exact scopes.

Graph uses a deadline per send, bounded read retries and no automatic mutation retries. Collection, response and in-memory cache limits reduce local resource consumption. Unknown response fields are stripped. Errors exclude provider messages, response bodies and untrusted headers. Returned task text remains personal and untrusted. The server supplies MCP instructions treating it as data. Agent behavior, transcript retention and actions taken through other tools remain outside this process's control.

The ownership check adds a Graph request before use of an existing list. It cannot be atomic with the subsequent action. An owned list can be shared outward. Strict response, identifier and URL validation can reject a legitimate future Microsoft format. A timeout during a write can mean Microsoft applied the change. Inspect the list before retrying. Create deduplication is best effort and process-local.

## Credential boundary

The app uses delegated device authorization in MSAL. You enter your password and any second factor on Microsoft's site. The normal Graph scope is Tasks.ReadWrite. MSAL supplies openid and profile for identity and offline_access for refresh. The account and grant are checked, including rejection of extra resource scopes. The HTTP and tool gates apply to this application. A bearer token acquired elsewhere can exercise its full grant. [Microsoft Graph permissions reference](https://learn.microsoft.com/en-us/graph/permissions-reference#tasksreadwrite)

The cache is plaintext in an owner-only per-client directory under `~/.config/microsoft-todo-mcp/<client-id>/`. The ordinary file is `write.json`, the scope-readonly file is `read.json`. Access tokens also live in process memory. File permissions assume trusted same-UID processes, ordinary POSIX ACLs, secure backups, and a trusted OS, TLS trust store and Node executable. An agent with shell or filesystem privileges as you may be able to read the cache independently of MCP. FileVault and encrypted backups help with offline theft. macOS Keychain would improve protection of copied cache files and backups. It would also introduce another native credential integration to maintain and test. This fork retains a bounded, auditable file cache. If a plaintext refresh token is unacceptable on your Mac, defer login until Keychain-backed persistence is implemented.

Stop all server processes before logout or switching accounts. Local logout cannot invalidate an already-issued token in memory or elsewhere. A crash during an atomic update can leave a private temporary cache file or an empty lock directory next to the cache. After all instances have stopped, remove any orphaned UUID-named .tmp cache files and the empty write.json.lock or read.json.lock directory before retrying. Treat backups and temporary files as credentials. [Local cleanup and remote revocation](README.md#stop-revoke-or-switch-accounts)

## Dependencies and verification

The three runtime dependencies are MSAL Node 7.2.2, MCP SDK 1.32.2 and Zod 4.6.7. The SDK brings HTTP-server dependencies transitively. The application instantiates stdio transport and has no HTTP listener. Production startup loads local dependencies and the local build. The pnpm lock pins resolutions and package integrity. Install uses a frozen lockfile with lifecycle scripts disabled. The old automatic prepare build was removed and esbuild replaces the tsup wrapper. CI has read-only repository permissions. Dependency publication, package-manager binaries, hosted CI actions and the local toolchain remain supply-chain trust points. Package integrity and advisory checks cannot detect all malicious updates.

- The initial baseline attempt lacked installed dependencies. An untouched archive of the original commit subsequently passed all 26 tests in six suites with the imported dependency set.
- The final frozen pnpm install, type check, ESLint, 69 tests in eight suites, production build, CLI version check and whitespace check passed. A separate real stdio smoke test launched the built executable with no client ID and a temporary home, enumerated 13 tools with no deletes, and checked signed-out status.
- The full dependency audit initially reported advisories affecting both runtime and development packages. After updates, `pnpm audit --prod` reported **zero known vulnerabilities**. The final full `pnpm audit` exited 1 with **one high advisory** for development-only picomatch 4.0.7. The registry listed no published patched version. The issue concerns expensive matching of adversarial extglob patterns. This dependency is present in development tooling and outside the deployed MCP runtime. Use trusted build/lint patterns and re-audit before updating or accepting untrusted tooling configuration. [picomatch advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)

Tests cover the hardened behavior with fake credentials, mocked HTTP and isolated cache files. They do not establish the security of Microsoft, pnpm packages, Codex or the host. The original cursor flaw was verified by source inspection, with mock request assertions against the fixed code. No live token transfer or pre-fix exploit was run.
